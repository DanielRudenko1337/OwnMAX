# OwnMAX

[English](README.md) | **Русский**

**Свой сервер для обмена сообщениями, групп, медиа и ботов с поддержкой протокола MAX.**

OwnMAX — независимый проект. Он не является официальным MAX, не связан с его разработчиками и не поддерживается ими. Название MAX используется для описания совместимости протокола, а не для обозначения партнёрства или одобрения.

Цель OwnMAX — запускать основные сценарии мессенджера на собственном сервере, со своей базой данных и настройками. Здесь находятся сервер на Python, отдельный SMS-сервис и пример бота. Исходники нативного клиента, APK и IPA в репозиторий не включены. Windows x64 preview распространяется отдельным архивом в [Releases](https://github.com/DanielRudenko1337/OwnMAX/releases/tag/v0.1.0). Для подключения нужен клиент, настроенный на ваш сервер; обычная установка официального клиента сама по себе этого не делает.

Если проект полезен, **поставьте OwnMAX звезду — Star вверху страницы GitHub**. Это простой способ поддержать его развитие и помочь другим найти проект.

## Клиент Windows

Скачайте preview ZIP из [Releases](https://github.com/DanielRudenko1337/OwnMAX/releases/tag/v0.1.0), распакуйте его, измените **`server.json`** рядом с **`START_OwnMAX.cmd`** и запустите лаунчер. В этой сборке адрес ограничен 12 ASCII-символами; для длинного адреса используйте короткий DNS-псевдоним. TLS, порты, вход и ограничения проверки описаны в [инструкции Windows](docs/WINDOWS.ru.md). Запуск нативного интерфейса на Windows для этого preview не проверен.

## Возможности

В сервере реализованы основные сценарии мессенджера. Полнота поддержки зависит от версии клиента и конфигурации сервера.

| Область | Что реализовано | Статус |
| --- | --- | --- |
| Авторизация | Запрос и проверка кода, вход, регистрация, пользовательские сессии | Коды тестового входа и регистрации выводятся в консоль; соответствующие запросы проверены для MAX |
| Учётная запись | Профиль, описание, аватар, сведения о сессиях; обработчики пароля и QR-авторизации MAX | Реализовано; полнота проверки зависит от функции |
| Контакты | Поиск и добавление контактов, сведения о пользователях, обновления присутствия | Реализовано |
| Сообщения | Отправка, получение истории, удаление, реакции, отметки прочтения и события набора текста | Реализовано; обновление и завершение активности проверены изолированно |
| Чаты и группы | Создание групп, участники, права доступа, управление чатами и ссылки-приглашения MAX | Реализовано; не все операции проверены на реальных клиентах |
| Папки | Получение и изменение папок; расширенные операции MAX | Реализовано; создание, чтение, изоляция пользователей и неверные запросы MAX проверены |
| Медиа | Загрузка и выдача фото, файлов, аудио и видео; подписанные ссылки и проверка владельца | Реализовано; жизненный цикл аватаров и права владельца проверены |
| Боты MAX | Создание и управление через менеджер, профиль и аватар бота, HTTP API сообщений, обновлений и загрузок | Реализовано; первый запуск бота и управление аватаром проверены |
| Звонки MAX | Сигнализация, состояние участников, личные и групповые сценарии, WebRTC-релей и передача экрана | Экспериментально; локальные сценарии аудио, экрана, выхода и повторного входа проходят проверки |
| Хранилище | SQLite, схемы создания пустой базы; адаптер MySQL | SQLite — основной проверяемый вариант; актуальность схемы MySQL для всех функций не подтверждена |
| Интеграции | Telegram, Firebase push, геолокация сессий и отдельный SMS-шлюз | Требуют собственной настройки; проверка внешних сервисов не входит в изолированный набор |

Это не обещание полной совместимости со всеми возможностями официальных приложений. Изменения протокола или конкретная версия клиента могут потребовать доработок. В частности, экспериментальные звонки нельзя считать готовой заменой промышленной инфраструктуры связи.

## Тестовый вход и регистрация

Для любого корректного номера сервер создаёт случайный шестизначный код и выводит его в **консоль процесса сервера**:

```text
OwnMAX: код входа или регистрации для <номер>: <6 цифр>
```

Такой код используется и при входе в существующую учётную запись, и при регистрации новой. Срок действия — пять минут. Введите код из консоли в подключённом клиенте.

**SMS и Telegram для доставки этих кодов не вызываются.** Это тестовая схема авторизации: доступ к консоли или журналу сервера позволяет увидеть коды входа. Не публикуйте журналы с действующими кодами.

Если сервер запущен в контейнере:

```sh
docker compose logs -f ownmax
```

## Быстрый запуск

Нужен **Python 3.12 или новее**. Следующие команды выполняются в корне репозитория:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -e .
cp .env.example .env
```

Отредактируйте `.env`: укажите адреса своего сервера и пути к TLS-сертификату и закрытому ключу. По умолчанию ожидаются `certs/cert.pem` и `certs/key.pem`.

Создайте пустую базу и запустите сервер:

```sh
python -m ownmax init-db
python -m ownmax serve
```

`init-db` создаёт SQLite-базу и ключи звонков. Существующая база не перезаписывается: повторная инициализация с тем же файлом завершится ошибкой. В репозитории находятся только схемы; готовой базы с пользователями и переписками нет.

Команда `ownmax serve` после установки пакета равнозначна `python -m ownmax serve`.

## Настройки

Основные параметры задаются в `.env`. Полный пример находится в [.env.example](.env.example).

| Параметр | Назначение |
| --- | --- |
| `host` | Адрес прослушивания TCP- и WebSocket-серверов |
| `oneme_tcp_port`, `oneme_ws_port` | Порты протокола MAX |
| `db_type` | Тип базы; пример использует `sqlite` |
| `db_file` | Необязательный путь к SQLite-базе; по умолчанию `ownmax.db` внутри каталога состояния |
| `OWNMAX_DATA_DIR` | Каталог базы, ключей и другого состояния сервера |
| `certfile`, `keyfile` | TLS-сертификат и закрытый ключ |
| `OWNMAX_PUBLIC_URL` | Публичный базовый HTTPS-адрес сервера |
| `OWNMAX_MEDIA_URL` | Публичный адрес медиасервиса |
| `OWNMAX_SIGNAL_URL` | Публичный WebSocket-адрес сигнализации звонков |
| `OWNMAX_TURN_URL`, `OWNMAX_STUN_URL` | Адреса вашей TURN/STUN-инфраструктуры |
| `OWNMAX_HTTP_HOST`, `OWNMAX_HTTP_PORT` | Адрес и порт внутреннего HTTP-сервиса; по умолчанию `127.0.0.1:9183` |
| `OWNMAX_CALL_PHONES` | Номера, которым разрешены экспериментальные звонки, через запятую; пустой список не разрешает звонки никому |
| `origins` | Допустимые Origin для WebSocket-подключений |
| `log_level` | Уровень журналирования |

Адреса `localhost` в примере нужно заменить своими публичными адресами, если клиент подключается с другого устройства. `127.0.0.1` означает локальный компьютер, а `0.0.0.0` используется для прослушивания сетевых интерфейсов.

Внутренний HTTP-сервис обслуживает медиа, Bot API и сигнализацию. Для публичного доступа настройте обратный прокси с TLS и поддержкой WebSocket. Одного изменения адреса в `.env` недостаточно: домен, сертификат, прокси и маршрутизация должны соответствовать друг другу.

## Звонки и передача экрана

Звонки находятся в экспериментальном состоянии и доступны только номерам из `OWNMAX_CALL_PHONES`.

Для работы вне одной машины нужны подходящие публичные адреса сигнализации и собственная TURN/STUN-конфигурация. Общий TURN-секрет должен совпадать со значением `turn` в закрытом файле `call-secrets.json` из каталога состояния. Этот файл нельзя добавлять в репозиторий.

Изолированные проверки покрывают передачу аудио с ненулевыми семплами, стабильность Opus при смене источника, пересылку данных экрана, независимый выход участника и его повторное подключение. Они не подтверждают качество связи во всех сетях или поддержку каждого режима реального клиента.

## Боты

Для MAX реализованы менеджер ботов и HTTP API с маршрутами `/botapi/me`, `/botapi/messages`, `/botapi/updates` и `/botapi/uploads`. Набор методов определяется обработчиком сервера и не заявляется как полная копия внешнего Bot API.

Пример бота находится в [examples/hello_bot.py](examples/hello_bot.py). Он отвечает на приветствие и команды `/start`, `/help`, `/ping`.

Передайте токен своего бота через переменную окружения, затем запустите пример:

```sh
python examples/hello_bot.py
```

Обязательная переменная — `OWNMAX_BOT_TOKEN`. Необязательные: `OWNMAX_BOT_API` для адреса API и `OWNMAX_BOT_STATE` для файла сохранения позиции обновлений. Токен не нужно вписывать в исходники или публиковать.

## Запуск в Docker

Нужны Docker и Docker Compose. Сначала подготовьте `.env` и файлы сертификата так же, как при обычном запуске.

```sh
docker compose build
docker compose run --rm ownmax python -m ownmax init-db
docker compose up -d
```

Порты в [compose.yaml](compose.yaml) соответствуют [.env.example](.env.example). При изменении портов обновите обе конфигурации. В контейнере база и ключи находятся в отдельном томе; сертификаты подключаются только для чтения. Внутренний HTTP-порт опубликован только на loopback хоста.

Docker-образ проверен сборкой и созданием пустой базы. Запуск всего стека через Compose в текущей проверке не выполнялся: на проверочной VDS не установлен плагин Compose.

## Проверки

После установки проекта:

```sh
python tests/run.py
```

Текущий набор включает **19 модульных тестов и 8 изолированных сценариев**. Они используют временное состояние, локальные соединения и синтетические учётные записи. Рабочая база, действующие токены и настоящие переписки для них не нужны.

Проверяются кодирование пакетов, токены и их ограничения, установка и инициализация базы без перезаписи, переносимые настройки, отсутствие комментариев в Python-коде, остановка задач перед закрытием базы, запросы кодов входа и регистрации, WebSocket-маршрутизация, папки MAX, пример бота, активность чатов, аватары, запуск бота и отдельные сценарии звонков.

Дополнительно проверены сборка Python-пакета, зависимости, запуск трёх локальных слушателей с временным TLS-сертификатом и корректное завершение процесса. Изолированные проверки не заменяют тестирование вашей конфигурации с реальными клиентами.

В [.github/workflows/checks.yml](.github/workflows/checks.yml) подготовлены проверки для GitHub Actions.

## Структура репозитория

| Каталог | Содержимое |
| --- | --- |
| `src/ownmax/core` | Базовые обработчики |
| `src/ownmax/infrastructure` | Транспорт, конфигурация, доступ к хранилищу и вспомогательные сервисы |
| `src/ownmax/protocols/max` | Обработчики MAX, чаты, боты, медиа и экспериментальные звонки |
| `src/ownmax/integrations` | Telegram-интеграция |
| `src/ownmax/storage` | SQL-схемы для создания пустой базы |
| `services/sms` | Отдельный SMS-шлюз; не используется для консольных кодов тестового входа |
| `examples` | Пример бота |
| `tests` | Модульные и изолированные проверки |

Рабочие базы, `.env`, закрытые ключи, сертификаты и клиентские сборки в исходный архив не включаются. Для своей установки создайте состояние самостоятельно.
